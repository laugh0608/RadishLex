# Agent 协作与执行规则

本文承接 `AGENTS.md` / `CLAUDE.md` 不适合启动时全量展开的稳定协作细则，面向项目所有者、维护者、实现者和 AI 协作者。本文不记录当前里程碑、批次、日期、提交、证据编号、实机资产或临时停止线；这些易变事实以[当前状态](status/current.md)、对应 runbook 和周志为准。

## 文档层级与判断顺序

### 三层职责

| 层级 | 职责 | 典型内容 |
| --- | --- | --- |
| 根协作入口 | 任何任务启动即生效的长期契约 | 协作原则、授权边界、项目红线、文档路由 |
| 稳定专题 | 按任务读取的详细规则和产品合同 | 架构、协议、隐私、平台、验证、安装、FFI、操作流程 |
| 当前状态与记录 | 会随阶段或现场变化的事实 | 当前顺位、临时门禁、“当前不做”、冻结资产、批次证据与历史流水 |

根入口不是项目手册副本，`docs/README.md` 也不是阶段规则正文。入口负责回答“去哪里读”，专题解释“长期规则是什么”，`current` 说明“现在处于什么状态”，runbook 说明“如何重复执行”，devlog 保存“已经发生了什么”。

### 判断顺序

1. 先遵循项目所有者在当前任务中的明确要求及其授权范围。
2. 再遵循 `AGENTS.md` / `CLAUDE.md` 的启动级长期约束。
3. 按 `docs/README.md` 和根入口路由读取当前任务需要的最少专题。
4. 通过当前代码、测试、配置、制品和实际系统状态确认实现事实。
5. 文档与实现不一致时不静默选择一方；先判断哪一侧过期，再在当前范围内统一口径。

## 任务开始与授权判断

### 识别任务类型

- 回答、解释、评审和状态报告以只读检查与证据支持为主，不自动授权写文件、提交、外部消息或系统动作。
- 诊断任务负责确定原因、影响和可验证结论；除非请求包含修复，不把诊断默认为实施授权。
- 设计任务负责固定目标、边界、备选方案和验证口径；没有明确实施要求时停在可执行方案。
- 实现或修复任务授权在约定范围内修改仓库、执行匹配验证并完成交付，不扩大到发布、推送或真实系统变更。
- 验证任务只执行请求范围和既有授权允许的检查；发现缺陷时先报告，不把验证请求自动扩展为重构。
- 发布、部署、系统写入和实机操作是独立权限层，必须取得当前任务的精确授权。

### 建立基线

- 开始任务先运行只读 Git 状态检查，确认分支、HEAD、ahead/behind 和工作区变化。
- 用户给出 commit、clean 或 ahead 状态时与实际基线交叉验证；不一致时先报告，不 reset、覆盖或清理来伪造预期基线。
- 工作区中的已有或并行改动默认属于用户；通过 `git diff`、文件时间和任务范围区分来源，只修改当前批次需要的部分。
- 当前阶段、停止线或下一顺位有关的问题默认先读 `docs/status/current.md`；只有信息不足时再读 roadmap 或当前明确引用的专题。
- 历史 devlog、archive、旧 RC 和已关闭整改材料不进入默认阅读链，只在追溯特定事实时按需读取。

## 方案、澄清与范围控制

- 架构、规则、接口、公共协议、依赖、隐私、许可证、平台、FFI ABI、安装事务、运行时行为或阶段边界变化，实施前说明目标、范围、非目标、影响和验证方式并等待批准。
- 小规模且低风险的 bug、文案、配置、文档、清理或验证补漏，在需求明确且不改变既有边界时可以直接实施。
- 仅在不同合理解释会明显改变结果、兼容性、数据模型、用户体验、外部状态或风险时阻塞澄清；可安全推断的小细节应说明假设并继续推进。
- 批准后的实现若出现新依赖、系统动作、跨模块扩张或用户可见行为变化，应暂停扩张并重新确认。
- 优先治理根因和同类问题，但不把“治理完整”当作无关重构、额外产品能力或范围蔓延的理由。
- 长期功能、跨语言能力、重要模块和阶段性交付进入代码前，应确认对应专题文档存在且边界清楚；小型修复不强制新建专题。

## 实现与质量原则

- 交付覆盖真实主路径、明确失败路径和必要恢复语义；不提交占位逻辑、局部演示或无法兑现文档合同的半成品。
- 抽象只服务于稳定边界、真实重复、复杂度下降或契约隔离；简单逻辑不通过多层 wrapper、factory 或转发函数制造间接性。
- 命名表达业务意图和技术边界，优先早返回、明确类型、浅层目录与顺序流程；避免动态字符串状态、函数嵌套和晦涩缩写。
- 错误处理覆盖明确的输入、IO、网络、权限、并发、FFI 和兼容风险；不吞异常、不伪造成功、不用默认值掩盖契约问题。
- 涉及 Rust、Go、Flutter、原生平台壳或跨语言 ABI 时，分别遵循对应语言和专题边界，不在调用侧复制另一层真相源。
- 核心数据、同步、删除、安装事务和平台系统状态必须保持确定性、可复核和失败关闭；未知状态不自动 retry、repair 或 fallback。

## 文档归位与维护

| 内容 | 真相源 |
| --- | --- |
| 项目定位、能力概览、稳定入口 | `README.md` |
| 当前里程碑、顺位、停止线、冻结基线 | `docs/status/current.md` |
| 长期阶段、交付物和退出标准 | `docs/roadmap.md` |
| 架构、模块职责与目录 | `docs/technical-plan.md`、`docs/repository-layout.md`、Boundary |
| 隐私、同步、协议、FFI 与平台合同 | 对应稳定专题和 ADR |
| 可重复系统操作、验收步骤与停止条件 | `docs/runbooks/` |
| 本周推进、提交、命令和历史事实 | `docs/devlogs/YYYY-Www.md` |
| 已关闭且退出默认阅读链的材料 | `docs/archive/` |
| 临时整改 | 仅由 `current` 显式激活的 `docs/remediation/` 专题 |

- 优先更新既有真相源；同一状态事实不复制到多个入口，历史段不回写成新事实。
- 新增或大改文档开头说明用途、读者和不包含内容；兄弟项目只写项目名与在线 URL，不把本机路径写入项目文档。
- 架构、协议、隐私、平台、目录、里程碑或验证口径变化时同步专题；每周重要推进按 Asia/Shanghai 追加当周 devlog。
- `current` 目标保持短小，只保留当前判断、停止线、下一步和索引；Guide、Runbook、Boundary 按职责拆分，普通活跃 Markdown 接近 500 行时优先拆职责。
- 阶段推进、证据冻结、现场变化和顺位调整不得反向修改根协作入口；只有长期协作合同变化时才同步 `AGENTS.md` / `CLAUDE.md`。

## 依赖、服务、系统与实机边界

### 需要当前任务明确授权

- 安装或更新依赖、下载 SDK / 模型 / 数据、改变全局工具链或生成范围外缓存。
- 启动长期服务、GUI、模拟器或真实平台进程；修改输入法、系统权限、Keychain、证书、全局配置、系统目录、dpkg、systemd 或 Fcitx 状态。
- kill / restart、合成按键、自动点击、切换输入源或其他可能干扰用户会话和人工验收的动作。
- 写入、恢复、复用、删除或清理真实 guest、数据库、staging、backup、receipt、operation、导入导出文件和证据资产。
- 推送、PR、Release、tag、远端配置、部署、发布或向外部人员和系统发送消息。

### 授权范围

- 执行前说明具体目标、命令或动作、环境、预期影响、停止条件和必要清理方式。
- 当前授权只覆盖已经说明的动作；目标、命令、环境或风险发生实质变化时重新确认。
- “继续”“完成”“不要停”等结果要求只延长既有范围内的推进，不自动授权新的系统写入、清理或发布动作。
- 已冻结或作为证据保留的资产只按 `current` 与对应 runbook 执行；不得从根入口或历史记忆推断当前可操作性。
- 默认在沙盒中执行仓库验证；只有权限、网络、证书或 PATH 限制导致结果失真时，才为必要验证申请最小范围提权。

## 验证与证据口径

### 风险分层

- 文案、纯文档和局部清理执行文本、链接、格式和差异检查。
- 单模块实现执行对应格式化、静态检查和定向测试；跨语言或公共边界补双方合同测试。
- 核心、数据一致性、安全、隐私、同步、FFI、安装事务和用户可见行为扩大到仓库级门禁及适用负向测试。
- 平台 build、repository-only smoke、模拟执行器和合成数据只能证明各自范围；真实输入、真实权限、真实安装和连续事务仍需独立人工或实机证据。
- 阶段性、高风险或发布候选交付运行 `./scripts/check-repo.sh`；fast / quick 入口只用于开发反馈，不作为最终结论。

### 交付表述

- 每项结论绑定实际执行过的命令、代码路径、产物或系统后置条件。
- 工具返回码、空输出、detached 声明或单一日志不能替代关键文件回读、结构化检查和正负向对照。
- 不把分散现场组合成同一连续 session，不把 repository-only 结果写成真实系统通过，不把 readiness 写成生产可用。
- 交付说明包含完成内容、验证结果、未执行项、环境阻塞和残余风险；不存在的证据不补写、不推断。
- 文档改动至少执行 `./scripts/check-docs.sh`、`./scripts/check-text-files.sh` 与 `git diff --check`。

## Git、提交与交接

- 变更前后检查 Git 状态和差异范围；不修改、暂存或提交本任务以外的文件。
- 串行普通任务直接在常态开发分支`dev`推进；只有项目所有者明确要求、外部贡献、并行写入、风险隔离或明确评审需求时才使用主题分支、额外worktree或Pull Request，完整拓扑见分支治理ADR。
- 禁止未授权 `git reset --hard`、checkout 覆盖、force push 或其他会丢失历史和用户改动的操作。
- 提交遵循 Conventional Commits，使用当前用户身份，不添加 AI 署名；代码、文档和治理按真实主题拆分。
- 范围清楚的小型本地提交可以直接完成；推送、PR、tag、Release、远端设置和部署必须另行授权。
- 交接时先给出结果，再说明关键变更、验证和剩余风险；文件引用使用可定位的仓库路径。

## 根协作入口维护

一条规则只有同时满足以下条件，才应进入 `AGENTS.md` / `CLAUDE.md`：

1. 跨任务成立，而不是某个功能、平台现场或批次专属。
2. 跨开发阶段成立，不会随当前里程碑自然失效。
3. 必须在读取专题文档前生效，否则容易造成高风险或大范围错误。
4. 无法只通过任务路由和对应专题可靠承载。

不满足全部条件的内容进入本协作专题、技术专题、`current`、runbook、devlog 或 archive。两份根入口必须逐字一致；修改任一文件时同步另一份，并由 `./scripts/check-docs.sh` 自动检查。
