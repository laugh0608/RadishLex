# 2026-W28 开发日志

本文档记录 2026-W28 周内 RadishLex 的阶段性推进事实、验证证据和后续建议，读者是项目维护者和后续 AI / 人工协作者。本文不承载长期架构设计、接口字段完整参考或历史推演；长期边界应回写到对应专题文档。

## 本周目标

- 继续推进 Phase 4 Flutter manager 同步入口的非上传产品化链路。
- 以本地 Docker / 本地 HTTPS、readiness 安全摘要和现有 fixture 为联调输入，固定恢复码 / 设备授权真实交互前的状态解释、错误分类、诊断脱敏和测试证据。
- 保持真实远端同步、恢复码生成 / 输入、join request 创建、授权成功和设备撤销路径关闭，直到平台私钥 backend、恢复 / 授权实现测试和发布级部署证据齐备。

## 2026-07-06

完成情况：

- 补齐 `manager_sync_readiness.v1` bridge 样本 fixture，覆盖 ready、部分阻塞和不安全输入。
- settings 页支持导入安全 readiness 摘要到当前 manager 内存态，并驱动设置页、同步页和诊断报告派生字段。
- 把 readiness 摘要导入校验收敛到 Dart mapper helper，固定合法样本、不支持格式、不安全 redaction 和未知字段降级语义。
- 补 action helper 覆盖，确认 settings draft 保存后不会丢失已导入 readiness，导入态诊断导出使用当前 snapshot。
- 补 `manager_sync_readiness.v1` 场景目录，覆盖 ready 但当前阶段关闭、恢复记录缺失、join request 过期、平台 backend 阻塞、部署证据不足、未知 native 状态降级、unsupported format 和 unsafe redaction 拒绝，并由 model 测试遍历复验派生结果。
- 将同一份 readiness 场景目录接入诊断报告字段回归和同步页代表场景可见层回归，确认 settings / sync / diagnostics 使用一致的 source、blocked flows、issue codes、next evidence、interaction plan、user sync enabled 和脱敏边界。
- 补 readiness envelope schema / hygiene 回归和 settings gate preview 代表场景回归，把 `manager_sync_readiness.v1` 固化为 bridge 接线前验收包；该验收包仍只校验非敏感摘要、降级规则和可见层一致性，不新增 `ManagerBridge` contract 或 C ABI。
- 补 `manager_sync_evidence_bundle.v1` 开发期预演 fixture，组合 readiness 摘要、`sync_connection_health.v1`、部署证据来源和设备 production gate，覆盖全部 ready 但当前阶段关闭、本地 HTTPS 可达但 readiness 阻塞、连接不可达但 readiness ready、不安全 connection summary 拒绝、不安全 readiness redaction 拒绝和未知 readiness 字段降级。
- 将 evidence bundle 场景接入 entry gate / diagnostics 完整目录、settings gate preview 代表场景和同步页代表场景，确认连接健康只是解释性证据，不会绕过恢复码、设备授权、发布级证据或当前阶段关闭门禁。
- 补 `manager_sync_action_command_preview.v1` 非执行命令预演层，从现有 `SyncInteractionEntryPlan` 派生四条未来操作的 action id、execution status、data policy 和 stop line，并接入 settings gate preview、同步页恢复码 / 设备授权 section 与诊断报告。
- 扩展 readiness / evidence bundle 场景回归，确认 ready 但阶段关闭映射为 `not_executable_current_phase`，readiness 阻塞映射为 `blocked_by_readiness`，不生成 bridge 命令或真实操作入口。
- 更新 `docs/status/current.md`、`docs/manager-sync-entry-boundary.md`、`docs/manager-settings-diagnostics.md` 和 `docs/manager-readiness-scenarios.md`，明确该能力不改变 `ManagerBridge` contract、不新增 C ABI、不打开真实同步或恢复 / 授权成功路径。

风险与未完成项：

- readiness 摘要导入仍是开发期本地联调入口，不是 bridge contract 或持久化 settings draft 字段。
- readiness 场景目录已经覆盖模型、settings gate preview、诊断报告和同步页代表场景；后续新增场景时应继续同步更新 fixture 预期与可见层断言，避免只扩展单侧测试。
- evidence bundle 仍是测试预演层，不通过 UI 导入，不写 settings JSON；后续若要扩展真实 bridge 输出，应继续复用 readiness mapper 和 connection health summary 的现有 envelope / redaction 校验。
- action command preview 仍是非执行摘要层，不创建 bridge 请求、不定义 C ABI、不携带恢复码、短码、签名、wrapped material、payload bytes 或请求 / 响应体；后续真实 bridge 命令前必须另补协议文档和测试。
- 平台私钥 backend、恢复码真实交互、设备授权成功路径和发布级部署证据仍是用户可用同步入口的停止线。
- 后续如果新增真实 bridge readiness 返回，需要继续复用当前 mapper allowlist、错误分类和诊断脱敏测试，不应把原始 native 错误、路径、token、恢复码、签名或 payload bytes 传入 UI。

下周建议：

- 继续围绕 readiness 摘要、evidence bundle 预演、只读 action intent 和 command preview 准备真实恢复 / 授权交互前的非敏感协议输入。
- 若触及 manager UI 可见行为，优先补 widget / helper 精准覆盖，再考虑扩大到 `./scripts/check-manager.sh` 和仓库级检查。
