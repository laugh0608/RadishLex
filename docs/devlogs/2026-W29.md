### 第一顺位：登录后只读复核

1. 开发者完成主动注销/重新登录后，先确认 Git 工作区和保留 bundle 路径，不重建、不复制、不启动 probe。
2. 使用公开 TIS API 只读记录 parent/mode 的 `matches`、enabled、selected、select-capable、type 和 languages。
3. 打开系统设置“键盘 -> 文字输入 -> 编辑 -> 添加”，只观察简体中文可添加列表和现有输入法列表；点击添加、启用、选择或移除前重新取得动作时确认。
4. 若 probe 仍不出现，记录“跨登录仍不进入系统设置目录”，停止候选测试；先决定并授权异常残留清理，不转向系统级安装、连续更换 ID/路径或 plist 试错。
5. 若 probe 出现，先记录 parent/mode 名称、图标和唯一有效 source，再申请添加/选择授权；真实候选输入只能由开发者使用实体键盘完成。

### probe 添加结果

- 取得明确授权后，系统设置已将“萝卜词核模式探针拼音”加入现有输入法列表；该行同时显示 parent 名称“萝卜词核 IMK 模式探针”。

- 下一步由开发者通过实体键盘或菜单栏选择 probe；真实候选输入继续只由开发者使用合成文本完成。

### probe 候选判定结果

- 开发者选择 probe 后，在 Codex 输入框输入合成字母，marked composition 与五个固定候选正常出现，首项“候选甲”具有视觉高亮。
- 按一次右方向键后视觉高亮没有移动；随后 Space 提交的仍是 index 0“候选甲”。因此视觉选择、callback 状态与最终提交没有形成预期的 index 1 一致结果，当前 reference 事件路由假设判定失败。
- 该证据只证明 reference 路径未产生选择迁移，尚不能区分方向事件未被面板消费、面板未改变选择或 callback 未触发。按停止线不再测试其他方向、Enter、数字或菜单，不修改当前 probe，也不生成新 build。
- 下一步先取得清理授权，切回系统拼音并在系统设置移除 probe，再执行精确清理和零残留复核；清理后才进入根因复盘。

### probe 清理门禁修正

- 开发者切回系统拼音并授权清理后，系统设置第一次移除 probe；完整重启设置后配置项按既有 macOS 行为回流，第二次移除后现有列表只剩简体拼音和美国。
- 第二次移除后公开 TIS 为 parent `enabled=0 selected=0 select_capable=0`、mode `enabled=1 selected=0 select_capable=1`。原清理脚本把任意 `enabled=1` 都视为用户仍启用，因此错误拒绝可发现但未添加的 mode；这与该 mode 在加入列表前的稳定属性冲突。
- 清理前门禁改为拒绝任何 `selected=1` source，或仍为 `enabled=1` 的不可选择 parent；只允许未选择、parent 已禁用但可发现 mode 仍 enabled 的回滚现场。删除后门禁继续要求 `matches=0 enabled=0 selected=0`，不放宽零残留验收。
- 修正后的入口删除精确 bundle、独立数据并终止同名进程；删除后 TIS 先保留 `enabled=0 selected=0` 缓存枚举，重新打开系统设置列表后两次查询均为 `matches=0 enabled=0 selected=0`，清理入口最终成功。

### 方向事件根因复盘

- 当前 macOS 26.5 SDK `IMKCandidates.h` 明确：`IMKCandidatesSendServerKeyEventFirst=YES` 时事件先到 controller，若返回未处理则继续送到候选窗；`candidateSelectionChanged:` 用于用户在候选窗移动时通知 controller。本轮实现与该公开契约一致，但 macOS 26.5.2 实机右方向后没有视觉或提交索引变化。
- 现有证据不能区分事件是否抵达候选面板、面板是否改变内部 `selectedCandidate`、或 callback 是否触发。下一方案不能继续依赖同一隐式 fallback，也不能回到已证伪的程序化选择。
- 单一候选方案是由 controller 保持优先接收，四方向显式调用候选面板继承自 `NSResponder` 的公开 `keyDown:`，记录调用前后 `selectedCandidate`、callback index 与最终提交；Space/Enter 继续由 controller 处理。该方案先评审，不在本批次直接生成新 build。

### probe 出现后的验收顺序

- 四方向视觉高亮、`candidateSelectionChanged:` 索引与 Space 最终提交必须一致。
- Space 提交当前合成候选；Enter 提交原始 composition；数字选择与 callback 语义明确。
- 输入菜单不得出现空白 parent、重复标题或图标错位。
- 失败时停止，不修改当前 probe 生成下一 build；无论结果如何都先完成设置列表、TIS、bundle、独立数据和精确进程清理。
