# 2026-W31 开发周志

本文记录 2026-W31 的阶段事实、验证证据、风险和交接事项，读者是 RadishLex 维护者与后续协作者。本文不替代 `docs/status/current.md`、架构边界、协议参考或 runbook。

## 本周目标

- 完成 M4-P03 Installer 生命周期治理，修复标准 Application 菜单与 `⌘Q` 退出缺口。
- 重新形成与代码身份一致的社区发布候选，完成自动载体门禁、独立下载与真实用户域 UX 复验。
- 冻结 macOS build 38 参考产品并转入 M5-P01，固定 Linux Fcitx5 第二平台决策、运行边界和停止线。

## 2026-07-27：Installer 生命周期治理与 build 38 本地候选

- 工作从干净且与 `origin/dev` 同步的 `e7e4e54` 开始。build 37 已完成 quarantine、固定路径启动、输入、repair、默认程序 remove 和数据保留证据，但实机发现 Installer 没有标准 Application 菜单，导致 `⌘Q` 无 Quit action；关闭最后窗口可以正常退出。
- 新增独立 `RLXInstallerApplicationMenu` 组件，由纯 AppKit 代码建立 Application 菜单、About、Hide、Hide Others、Show All 和 Quit。Quit 使用 responder chain 的 `terminate:` 与 Command+`q`；既有 `applicationShouldTerminateAfterLastWindowClosed` 保持不变。
- 正常退出契约没有进入 Driver、Executor 或 receipt：UI 不清理或改写 guard、staging、backup、receipt 与历史 operation，重新打开仍从持久化状态形成 fresh snapshot。原生 contract 现验证 Application 菜单、Quit selector、key equivalent 和命令修饰键，源码门禁继续约束 UI 不跨越事务/TIS/路径边界。
- 因 Installer executable 内容变化，版本从 `26.7.1 (37)` 递增到 `26.7.1 (38)`，并同步 root `version.json`、产品 metadata、Flutter pubspec 与 macOS Xcode build number。build 37 的历史载体、摘要和实机证据未被覆盖。
- 使用本机既有 Homebrew `librime 1.17.0` 显式 include/lib 路径完成双 bundle 产品装配；首次沙盒构建因 Flutter SDK cache 位于工作区外而被权限阻断，获准后仅在真实构建环境复跑同一装配入口。没有安装依赖、修改全局工具链、启动 GUI 或访问真实用户域。
- build 38 已生成 strict ad-hoc Installer 和未公证社区 DMG。`RadishLex-26.7.1-38.dmg` 大小为 `32196093` bytes，SHA-256 为 `f171e74bdc0a429655a84b30429481bce3926b17076d09298feed77d9ce4ce4e`；`CommunityReleaseEvidence.json` 绑定相同值、release identity SHA-256 `36f416fbbc5719f60b1535c742285520f9761850ccf3ab2f8c4577f79117205b`，并明确 `apple_notarized=false`。
- 本批以 `642cbb4 fix(installer): add standard application menu` 提交并推送到 `origin/dev`。远端 draft Release 标题已对齐为 `RadishLex 26.7.1 (38) 社区候选`，build 37 DMG/checksum 在 build 38 三项资产全部达到 `uploaded` 且 size/digest 匹配后才删除；终态只保留 build 38 DMG、checksum 和 evidence，仍为 draft、`publishedAt=null`，未创建正式 Git tag。

- 用户随后在已登录 Chrome 中手动点击 build 38 DMG，形成真实独立下载副本；文件大小 `32196093` bytes、SHA-256 `f171e74bdc0a429655a84b30429481bce3926b17076d09298feed77d9ce4ce4e`，与本地候选逐字节比较一致。副本带有 Chrome 写入的 `com.apple.quarantine`、provenance 和 GitHub Release 来源元数据，临时签名下载 URL 不写入仓库。

- 全程只读输入源监视仅看到系统拼音 `com.apple.inputmethod.SCIM.ITABC`，没有 RadishLex 被选中。两个清理测试数据 baseline 入口因要求 `runtime_data=absent` 而失败关闭；当前保留数据现场不满足其前提，因此没有执行清理或为通过脚本改写现场。

- 安装后两个 bundle 的严格 codesign、冻结 ProductManifest、ReleaseIdentity 和逐节点无 quarantine 复验通过。TIS 显示 RadishLex 拼音已注册并启用但未选择，输入法进程停止；Application Support、runtime data、userdb 与 sidecar 继续存在。

- 退出后只读状态确认 Manager/InputMethod 进程停止，RadishLex 拼音仍未选择，userdb 保留且临时 sidecar 已清零。截图只含公开合成词条，不提交到仓库。

- 切回后 RadishLex 未被选择，但 InputMethod 仍从固定路径正常驻留，userdb 与运行时 sidecar 存在；这是 macOS 输入法生命周期现场，不把“切回中立 source”误记为进程退出，repair 前另走显式静止流程。

## 2026-07-27：冻结 macOS 参考产品并进入 M5-P01

- 产品决策调整为暂不发布 build 38，不创建正式 Git tag，不把远端 draft 转为正式 Release；本地 7 个实机证据提交继续保持未推送。build 38 assembly、SHA-256/evidence、验收记录和默认 remove 后的数据语义作为 macOS 冻结参考保留。
- 公开发布与平台验收分离：计划内 macOS、Linux Fcitx5、Android、Windows 和 iOS 仍按单一主线顺序分别取得退出证据，待各平台完成后再进行统一发布评审；不以统一发布评审替代平台输入、个人化、隐私和安装维护证据。
- 新增 ADR 0009，第二真实平台固定为 Linux Fcitx5，后续依次为 Android、Windows 和 iOS；M5 期间不并行实现其他平台壳。
- 新增 Linux Fcitx5 平台边界，固定 C++/CMake addon、ABI v9 复用、owner-thread/session、Fcitx input panel、LearningContext、XDG resolver、Manager 同库、构建依赖和真实桌面验收边界。
- 路线图将 M5 分为 P01 设计、P02 addon/FFI/build、P03 真实输入与隐私、P04 Linux Manager 与个人化、P05 安装维护五个批次。P01 不创建占位平台目录，也不把文档批准写成 Linux 能力已经实现。
- 同步更新当前状态、技术方案、仓库结构、README 与 `AGENTS.md`/`CLAUDE.md` 快速认知；真实用户同步继续关闭。
- `./scripts/check-docs.sh` 与 `./scripts/check-repo.sh` 通过，只保留既有 `docs/sync-server-api-storage.md` 508 行预算提醒；M5-P01 完成，当前主批次前移到 M5-P02。
