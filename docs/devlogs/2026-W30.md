## 2026-07-21：M4-P02 receipt 文件系统切面

- `ime-product-upgrade` 新增 `VerifiedDataRoot` 与 `UpgradeReceiptStore`：只接受 canonical、同 owner、`0700` 的固定数据根，创建并锁定 `.radishlex-upgrade-v1` 状态目录；加载与持久化前都会重验 data root、状态目录和既有 receipt 身份，未知对象、symlink、hardlink、mode/owner/device/inode 漂移均失败关闭。
- receipt 固定使用 `receipt.json.tmp` 的 `create_new` 写入、`0600`、文件 `fsync`、原子 rename、状态目录 `fsync` 和写回复验。既有 operation 的 metadata 不可改写，artifact 只能追加，每次最多持久化一个合法状态；相同 bytes 可幂等重放，新 operation 不得覆盖既有 operation。中断临时文件当前保留现场并返回稳定错误，自动恢复决策留给后续 crash-recovery 切面。
- 跨进程 guard 使用 root-owned sticky 临时根中的短 Unix socket，名称绑定 uid 与 data root device/inode，不包含 home、真实路径或内容 hash。活动 socket 拒绝重入；只有身份、owner、mode、type 都符合且连接明确 `ConnectionRefused` 的精确 stale socket 可以恢复。symlink/普通文件保持原样并失败关闭，Drop 只删除取得时同一 inode 的 socket。
- 文件系统验证确认 APFS 目录 link count 会随目录项变化，因此目录 link count 只作 receipt 观察字段，稳定身份比较使用 type/device/inode/owner/mode/canonical path；普通文件仍严格要求 `link count = 1`。同时把 guard 从深层数据目录移到短临时路径，避免 macOS `sockaddr_un` 长度上限使合法 Application Support 路径无法绑定。
- 生产文件系统实现与测试拆为 `src/filesystem.rs` 和 `src/filesystem_tests.rs`，避免单文件触及 1000 行治理线。真实本机环境下 `ime-product-upgrade` 17 项测试与 `clippy --all-targets -- -D warnings` 通过；沙盒仅因 Unix socket 权限隔离产生 4 项 `Io`，同批非 socket 用例正常通过。

## 2026-07-21：M4-P02 SQLite 一致快照切面

- 上一批升级边界、userdb inspection/migration contract、receipt 原子持久化与跨进程 guard 已提交为 `9497dfe feat(upgrade): 建立产品数据升级协调基础`；未推送远端。
- `ime-userdb` 在既有 `rusqlite 0.32.1` 上启用 `backup` feature，新增 `estimate_snapshot` 与 `create_consistent_snapshot`。源连接保持只读事务，backup 纳入未 checkpoint WAL 的可见页；目标必须是调用方预建的独立空普通文件，完成后转为 standalone `DELETE` journal、通过 `quick_check(1)` 并与源事务 schema/page 元数据一致，不执行 migration、不留下 WAL/SHM。schema 0 零字节数据库按一个 materialized header page 估算并保持可迁移语义。
- `ime-product-upgrade` 只接受 fixed data root 下的 `userdb.sqlite3`，只写 `.radishlex-upgrade-v1/source-snapshot.sqlite3.tmp` 与最终 snapshot。源和目标校验 type/device/inode/owner/mode/link/byte length；成功顺序为临时文件、SQLite backup、文件 `fsync`、原子 rename、目录 `fsync`、先持久化 snapshot identity、再推进 `snapshot_ready`，原库字节不被改写。
- 空间预算固定为 `3 * logical_snapshot_bytes + 64 MiB`，覆盖 snapshot、migration candidate、切换/rollback 工作余量和最低 reserve；overflow 或 available bytes 不足会在创建临时文件前失败。真实 available bytes 仍由后续固定 macOS 文件系统 adapter 提供，核心不引入平台 `unsafe` 或接受 UI 自定义路径。
- 故障注入覆盖临时文件创建后、backup 后、rename 后和 receipt evidence 后。staged snapshot 或无 receipt identity 的最终 snapshot 会使启动加载失败关闭；已持久化 identity 但仍为 `quiesced` 的 receipt 可以读取证据，当前不会自动跨状态，留给后续 crash-recovery 编排。
