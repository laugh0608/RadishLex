# 2026-W30 开发周志

本文记录 2026-W30 的阶段事实、验证证据、风险和交接事项，读者是 RadishLex 维护者与后续协作者。本文不替代 `docs/status/current.md`、架构边界、协议参考或 runbook。

## 本周目标

- 完成 Manager 通过真实 Rust bridge 执行的本地 HTTPS 合成同步资格链。
- 固定 Rust-owned run、单运行所有权、取消/超时、transient token/CA 与脱敏结果 contract。
- 复用既有 sync/crypto/userdb orchestration，经真实 Caddy HTTPS 证明双客户端同步、冲突恢复、第二轮收敛与资源清理。
- 保持真实用户同步、恢复/授权/撤销产品入口和 `user_sync_enabled` 关闭。

## 2026-07-20：Manager 同步资格执行批次启动

- PR #5 已把上一阶段成果合入 `master`，并以 `a73adab` 将最新 `master` 回同步到共享 `dev`；远端拓扑闭环、工作区干净。
- 复核确认 `ime-sync` 不能反向依赖 `ime-userdb`，本地输入 `ime-runtime` 明确不负责远端同步，`ime-ffi` 也不能直接组合网络和数据库。因此新增 `ime-sync-runtime` 作为 Manager 同步产品组合层，依赖稳定 sync/userdb/crypto 边界并向 FFI 提供 Rust-owned run。
- 本批只允许 loopback HTTPS、隔离合成 P2 与单次调用 transient 参数，不访问真实 userdb 或 Keychain/Secure Enclave，不改变产品资格和用户同步总 gate。
